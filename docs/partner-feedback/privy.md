# Partner feedback: Privy. No bounty targeted; used for email sign-in + embedded wallet (2026-10-05/06)
- Google login needs your own OAuth client id/secret in the dashboard; I only wanted a quick login, so I shipped email-only. A "use Privy's dev Google credentials for testing" toggle would remove that step.
- `@privy-io/react-auth` 3.47 pulls a large dependency tree (WalletConnect, wagmi connectors, x402) into a viem-only app: `pnpm 12` refused to install until I reviewed install scripts for `@reown/appkit`, `bufferutil`, `keccak`, `utf-8-validate` (all set to not run), and `pnpm audit --prod` then reported 4 advisories (ws high + moderate, uuid, decode-uri-component), all transitive through that tree. Fixed with `pnpm overrides`; I did not need any of those packages.
- Types: `wallet.getEthereumProvider()` returns a provider whose `on()` type is not assignable to viem's `EIP1193Provider`; needed a cast to hand it to `createWalletClient({ transport: custom(provider) })`.
- Dashboard: "Automatically create embedded wallets" for all users also created a Solana wallet because both chains were ticked; harmless but unexpected.
- Works well: the embedded wallet signs `personal_sign` and sends Monad testnet transactions through viem unchanged; first subscribe + unlock with an email-only user worked end to end (txs in docs/evidence.md). The console logs "The configured chains are not supported by Coinbase Smart Wallet: 10143" (informational).
- Not tried: server wallets with policies (a Privy bounty would need use beyond sign-in; the starter-funds wallet is a plain env key).
