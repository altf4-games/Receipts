# Envio: friction log (written as it happened)

1. **`envio init template` fails on a fresh pnpm 12 machine**: `ERR_PNPM_IGNORED_BUILDS: Ignored build scripts: esbuild@0.27.7` aborts "installing dependencies", leaving a half-initialised project. Fix: allow esbuild's build script (`allowBuilds`/`onlyBuiltDependencies` in the project's own `pnpm-workspace.yaml`). A note in the quickstart for pnpm 10.26+/11+ would save the first 10 minutes. Envio Cloud's pnpm 10.32 accepts the same project (I tested `pnpm@10.32.0 install --frozen-lockfile` and `envio codegen` on Node 24 before connecting).
2. **A monorepo workspace confuses the indexer install.** Inside a pnpm workspace, `pnpm install` in `indexer/` reinstalls the whole workspace and trips the ignored-builds error. Making `indexer/` its own project (own `pnpm-workspace.yaml`, removed from the root list) fixed it. The Cloud docs mention a "root directory" setting but not this.
3. **A contract cannot start before its chain**: `The start block for contract "PerplAccounts" is less than the chain start block. This is not supported yet.` I wanted `AccountCreated` from block 0 and position events from the Receipts deploy block on the same address. Workaround: chain `start_block: 0` plus an explicit per-contract `start_block` on every contract, and two logical contracts (`PerplAccounts`, `PerplTrades`) pointing at the same Exchange address. It works, but the error is only raised by the test indexer / at run time, not by `envio codegen`.
4. **`start_block: latest` cannot be combined with per-contract overrides** (documented), so mainnet carries only one contract entry.
5. **The test indexer silently drops events below a contract's start block** and then reports `N items you passed to simulate never reached a handler`. The message is good once you know why; my first simulated blocks (100) were far below the real start blocks (68M).
6. **Simulated events need distinct logIndex** or must omit it: `items at index 0 and 1 ... both resolve to block 100, logIndex 0`. My helper set `logIndex: 0` explicitly. Clear message; the docs example does not show the pitfall.
7. **Resume after a schema change loses entity data silently.** After adding entities and restarting `envio dev`, the log said "Found existing indexer storage. Resuming indexing state..." and queries returned 0 rows while progress showed the chain head. `envio stop` followed by `envio dev` (a full reset) fixed it. A warning "schema changed, resume skipped history" would prevent confusion.
8. **The public Envio Cloud endpoint does not expose Hasura aggregates** (`Call_aggregate` -> `field 'Call_aggregate' not found in type: 'query_root'`) and takes no admin secret; the local `envio dev` Hasura exposes both. Code that works locally with `_aggregate` fails on the cloud; I count client-side instead.
9. **Local port clash**: a second `envio dev` after a hard kill fails with `port 9898` in use until `lsof -ti :9898 | xargs kill -9`.
10. **Docker must be running for `envio dev`** and the error names the OrbStack socket path (helpful). First start of OrbStack took ~10 s.
11. **HyperSync was easy and fast**: the full testnet + mainnet history synced in ~40-65 s from a free token; rapid manual `/query` calls get `429 Too Many Requests` (retry with backoff).
12. **Good**: `envio tools search-docs / fetch-docs` inside the CLI gave me the current V3 syntax without leaving the terminal; `createTestIndexer().process({ simulate })` made handler tests fast and deterministic; `chain_metadata` in GraphQL made "indexed to block N" and an exact L11 comparison possible.
